# 大規模言語モデルによる AIF 議論グラフ抽出の精度評価

人手アノテーション済みの公開コーパスを正解として、LLM が対話の書き起こしから作る
AIF / IAT 議論グラフの正しさを測った。本報告は 2 部からなる。

- **第 I 部　AIF 抽出の精度と手法** — LLM がどこまで正しいグラフを作れるか。
  **LLM が自明な基準線に負ける層がある**ことが分かった。
- **第 II 部　グラフ比較の精度と手法** — 生成グラフとゴールドをどう比べれば正しく測れるか。
  評価指標そのものの妥当性を点検しながら進めたところ、**指標の設計が結論を 2 度反転させた**。

第 I 部の数値はすべて第 II 部の指標で測っているため、第 I 部の結論は第 II 部の答えに依存する。

- 実験コード・プロンプト・集計値: 本リポジトリ（[`README.md`](../README.md)）
- 集計値は [`data/metrics/*.csv`](../data/metrics) に置いた。本文の数値のうち CSV の列から計算できるもの
  （GED、関係・命題の P/R/F1、事前登録比較）は CSV から再計算して照合した（§16.3）。
  数値はすべて、§15.2 の不具合を修正した実装で再評価した値である。
  図は [`scripts/make_report_figs.py`](../scripts/make_report_figs.py) で生成したが、
  距離帯・閾値曲線・等級分布は CSV に無い列を使うため、生出力（`out/`）が必要である。

## 1. 背景・目的

### 1.1 背景

議論マイニングでは、対話から議論の構造（主張・根拠・反論・言い換え）を取り出して
グラフとして表す。その標準的な表現が AIF（Argument Interchange Format, Chesñevar et al., 2006）であり、
対話の時間的な進行と論理構造を結びつける理論が IAT（Inference Anchoring Theory, Budzynska & Reed, 2011）である。

AIF では議論を次のノードで表す。

| 記号 | 名称 | 内容 |
| --- | --- | --- |
| L | locution | 発話。話者が実際に言った単位 |
| I | information | 命題。発話の内容を独立した平叙文に直したもの |
| RA | rule application | 推論。前提が結論を支持する |
| CA | conflict application | 対立。一方が他方を攻撃する |
| MA | preference/rephrase application | 言い換え。一方が他方を言い直す |
| YA | illocutionary anchoring | 発話行為。発話がどの力で命題や関係を生むか |
| TA | transition | 遷移。発話から発話への移行 |

近年、この構造を LLM に抽出させる試みが増えているが、
**抽出されたグラフがどれだけ正しいかを公開ゴールドに対して定量化した報告は少ない。**
下流タスク（検索・要約・議論生成）の性能で間接的に評価する研究が多く、
「グラフが正しいから効いた」のか「粗いグラフでも効いた」のかを切り分けられない。

### 1.2 目的

本研究の問いは 3 つである。

- **RQ1**（第 I 部）— LLM が生成した AIF グラフは、人手のゴールドアノテーションとどれだけ一致するか。
- **RQ2**（第 I 部）— その不一致は、AIF のどの層（発話の分割・命題の再構成・発話行為・命題間の関係）から来ているか。
- **RQ3**（第 II 部）— グラフ編集距離（GED）という単一の数値は、実際の一致・不一致をどこまで正しく反映するか。

RQ3 を独立した問いとして立てたのが本研究の特徴である。
後述するとおり、**指標の定義を変えると条件の順位が反転した**ため、
RQ1・RQ2 の答えは RQ3 の答えに依存する。

## 2. 共通の方法

### 2.1 データ

| 項目 | 内容 |
| --- | --- |
| コーパス | QT30（AIFdb corpora）。BBC "Question Time" 30 回分 |
| 出典 | Hautli-Janisz et al. (2022) |
| アノテーション | IAT による人手アノテーション |
| 人手一致率 | CASS = 0.56 |
| 取得範囲 | 6 サブコーパス（= 6 エピソード）、274 ノードセット |

QT30 を選んだ理由は、(a) 司会・パネル・聴衆による**多者対話**であり独話のエッセイより
実際の議論に近いこと、(b) L / YA / TA を含む **IAT の全層**が入っていること、
(c) アノテーション前の**素テキストが同梱**されていることである。

**分割はサブコーパス（= 1 エピソード）単位で固定した。**
同一エピソード内のノードセットは同じ論題・同じ話者の連続した区間なので、
ノードセット単位で分けるとリークになる。

| 分割 | エピソード | 条件に合うノードセット |
| --- | --- | --: |
| dev | 4June2020 / 18June2020 / 30July2020 | 137 |
| test | 28May2020 / 2September2020 / 22October2020 | 124 |

プロンプトの設計は dev でのみ行い、**報告する数値はすべて test から取る**。
本報告の主要な結果は test の **124 件すべて**（正解関係 1,090 本）に基づく。

前処理（`aif.Normalize`）で、QT30 の収録ツールが残す孤立 L-node（次数 0 の複製、
全体の 52.6%）と、AIF のメタモデルに無い形の辺を除いた。命題と関係は保持する（単体テストで固定）。

### 2.2 統計

対応のある比較（同じノードセット同士）。差の信頼区間は対応ありブートストラップ
（10,000 反復・seed 固定）、p 値は Wilcoxon 符号順位検定（両側・正規近似）、効果量は Cliff's delta、
多重比較補正は Holm。**事前登録した 5 比較の族に対してのみ補正を掛ける。**

実測した対応差の標準偏差から、本標本で検出可能な最小差は次のとおりである。

| 指標 | 対応差の sd | n=124・Holm 5 比較での検出限界 |
| --- | --: | --: |
| 関係F1（厳密） | 0.165 | **0.052** |
| 関係F1（無向） | 0.152 | 0.048 |
| 命題 GED | 0.127 | 0.040 |

**0.05 未満の差は本標本では検出できない。** 以下で「差がない」と述べる箇所は
すべてこの限界の下にある。

- test は 124 ノードセット・正解関係 1,090 本である。
- E1–E3（§4.3）は n=20〜60 で実施しており、検出限界はさらに大きい（n=60 で 0.071）。
- n=60 で得た値は n=124 では楽観的であったことが判明した
  （v3 の厳密 F1: 0.339 → 0.296）。追加した 64 件の方が難しい。

### 2.3 再現性

LLM 応答と埋め込みの両方をディスクにキャッシュしているため、
同じ入力・同じプロンプト版なら再実行で同じ数値が出る（費用も 0）。
プロンプトは版ごとに別ファイルとし、本文の SHA-256 を結果に記録している。

**ただし本リポジトリにコーパス本文および生成グラフは含まれない**（再配布条件が
確認できないため）。再現には AIFdb からの取得が必要である。
本文を含まない集計値は `data/metrics/*.csv` として公開している。

# 第 I 部　AIF 抽出の精度と手法

## 3. 課題 — LLM の議論グラフ抽出に固有の難しさ

1. **出力量を自分で決められない。** 「関係をすべて挙げよ」という指示に対して、
   LLM はどこで打ち切るかの基準を持たない。後述するとおり、生成した関係の過半数が
   ゴールドに対応しない。
2. **正解が一意でない。** QT30 の人手アノテータ間の一致は CASS = 0.56（moderate）であり
   （Duthie et al., 2016）、特に RA の向きはアノテータ間でも揺れる。
3. **層が多い。** 発話の分割・命題の再構成・発話行為・命題間の関係のどこで誤ったのかを
   切り分けないと、改善の方向が決まらない。

## 4. 手法

### 4.1 抽出パイプライン

IAT のアノテーション手順（segmentation → classification → relation identification,
Lawrence & Reed, 2020）をそのままなぞる 3 段階とした（`internal/aif/annotate.go`）。

```
stage 1  書き起こし → L-node（話者 + 発話単位）
stage 2  L-node     → YA-node（発話行為） + I-node（命題）
stage 3  I-node     → RA / CA / MA
```

- **TA-node は隣接する L-node の間に機械的に張る。** IAT では発話の連なりそのものが遷移であり、
  LLM に当てさせると「遷移を当てる課題」に化けて評価が濁るためである。
- **stage 2 の発話行為の選択肢は、L-node に anchor できる力だけに絞る**（v2 以降）。
  Arguing / Restating / Analysing は遷移（TA）に anchor される力であり、発話単位の選択肢に
  混ぜてはいけない。QT30 のゴールドでも L→I の anchor は Asserting が 90.7% で、Arguing は 0.1% しかない。
- **関係を担う YA は、両端の発話の間の TA に anchor する。** 隣接しない発話どうしの関係には
  TA が無いので YA も作らない。
- すべて Structured Outputs（JSON Schema strict）で受け、生レスポンスを保存する。

各段階で LLM に与えた規則（プロンプト）と、ハーネスが機械的に課した規則（構成規則）は、
付録 A にすべて言語化した。前者は LLM が従う保証の無い指示、後者は出力の形を決定的に決める規則であり、
結果を解釈するときは区別が要る（例: CA / MA の向きを時間順にする規則は前者で、ハーネスは検査も補正もしない）。

入力条件は 2 つある。

| 条件 | 発話分割 | LLM に任せるもの |
| --- | --- | --- |
| `gold-loc` | ゴールドの L-node を与える | 命題・発話行為・関係（stage 2・3） |
| `e2e` | LLM に任せる | 全段階（stage 1〜3） |

生成したグラフは AIF メタモデル検査（S-node の入出力の数、YA の anchor 位置、
TA が L→L であること等、10 規則）を通す。**本実験の全条件で違反は 0 件**であった。

### 4.2 基準線

LLM を使わない下限を 2 本置いた。**どちらも本研究の結論に不可欠である。**

| 記号 | 内容 | 何を測るための下限か |
| --- | --- | --- |
| 基準線① | 関係を 1 本も出さない（発話をそのまま命題とみなし、発話行為はすべて Asserting） | グラフ全体の編集距離・命題層・発話行為層 |
| 基準線② | **隣り合う命題を全部つなぐ**（種別は最頻の RA、向きは後→前）。関係（stage 3）には LLM を使わないが、命題と発話行為は w1 と同じ stage 2 の LLM 出力を使う（付録 A.6.4） | 命題対を選ぶ能力 |

基準線②を置くまで、「どの命題対がつながっているか」の判断で
LLM が自明な規則に負けていることに気づけていなかった。

### 4.3 実験（変数）

実験は 5 本行った。**1 世代につき 1 要因だけを動かす**方針を貫いた。
（指標の版を動かした実験 M は第 II 部 §12 で扱う。）

| # | 実験 | 分割 / n | 動かした要因（水準） | 固定したもの |
| --- | --- | --- | --- | --- |
| E1 | プロンプトの版 | dev / 20 | 仕様の伝え方 v1 → v2 → v3 | モデル・入力条件 |
| E2 | モデル | test / 60 | `gpt-5.6-luna` / `gpt-5.6-terra`（単価 10 倍） | プロンプト v3 |
| E3 | 4 つの介入 | test / 60 | v3 / v4 / v5 / v6 / w1 | モデル・入力条件 |
| E4 | 基準線と抽出方式 | test / **124** | 基準線① / 基準線② / v3 / w1 | モデル・入力条件 |
| E5 | 関係の等級づけ | test / **124** | 3 値（c1） / 5 段階（g1） | 関係プロンプト本文・命題層 |

**E1（仕様の伝え方）** — v1 → v2 → v3 の差は正解に合わせたチューニングではなく、
IAT が定めているのに実装が伝えていなかった規則を足したものである。
v2 で「発話行為は anchor 位置で決まる」を、v3 で「MA / CA の向きは対話の時間順」
「MA は質問と応答の間にも成り立つ」「言い換えの連鎖は 1 本ずつ記録する」を足した。

**E3（4 つの介入）** — v4: 遠距離の関係を抑制する規則の是正。v5: 関係ごとに
3 値の確信度を申告させる。v6: v5 に生成後の検証パス（1 本ずつ keep/drop）を足す。
w1: 命題の過剰な書き換えを抑える規則を stage 2 に足す。

**E4（抽出方式）** — 基準線②（隣接を全部つなぐ・関係に LLM を使わない）を初めて導入した。

**E5（等級づけ）** — 過剰生成を絞るための等級。c1 は「注釈者はこれを記録するか」
（3 値: high/medium/low）、g1 は「dst が src にどれだけ依存しているか」
（5 段階、各段に操作的な判定手順つき）。**閾値は生成後に動かす**（等級は S-node に載る）ので、
1 回の生成から複数の動作点が得られる。

## 5. 結果

以下の数値はすべて **test 124 件・`gpt-5.6-luna`・GED 0.3・一様重み・micro 平均**である
（指標の定義は第 II 部 §10）。入力条件は `gold-loc` である。

> **§15.2 の不具合修正について。** 本節の数値は、不具合を修正した実装で、報告時と同じ生成物
> （キャッシュ済みの LLM 応答と埋め込み）を再評価したものである。修正で値が変わったのは
> §5.1 の g1・c1（全部）の厳密 AP/AR/F1 と c1 の命題 GED（いずれも +0.001）、§5.3 の帯ごとの AP だけである。

### 5.1 関係層 — LLM は自明な基準線に負ける（RQ1）

![図2](figures/rep_fig2_precision_recall.png)

| 条件 | 厳密 AP | AR | F1 | 無向 AP | AR | **無向 F1** | 生成本数 | 命題 GED |
| --- | --: | --: | --: | --: | --: | --: | --: | --: |
| 基準線①（関係なし） | – | – | 0.000 | – | – | 0.000 | 0 | **0.483** |
| **基準線②（隣接を全部）** | 0.122 | 0.198 | 0.151 | 0.410 | **0.667** | **0.508** | 1,775 | 0.217 |
| v3 | **0.306** | 0.287 | **0.296** | 0.473 | 0.444 | 0.458 | 1,023 | 0.401 |
| w1 | 0.298 | 0.297 | 0.298 | 0.457 | 0.455 | 0.456 | 1,086 | 0.391 |
| g1（5 段階・全部） | 0.285 | 0.277 | 0.281 | 0.466 | 0.452 | 0.459 | 1,058 | 0.393 |

「厳密」は種別（RA/CA/MA）と向きの両方が一致、「無向」は命題対を当てたかどうかである。

事前登録した 5 比較（Holm 補正）。値はノードセットごとの指標の対応差である。
**無向 AP の 2 比較はノードセットごとの精度（macro）で比べている**ため、上の表の micro の差とは一致しない（§15.1(c)）。

| 比較 | 指標 | 平均差 | 95%CI | p | p(Holm) | Cliff's δ | 勝ち |
| --- | --- | --: | --- | --: | --: | --- | --: |
| **基準線② − v3** | 無向 F1 | **+0.054** | [+0.018, +0.089] | 0.0031 | **0.0093** | +0.19 small | 74/124 |
| **v3 − 基準線①** | 命題 GED | **−0.082** | [−0.114, −0.050] | <0.0001 | **<0.0001** | −0.30 small | 41/124 |
| c1 high − v3 | 無向 AP（macro） | +0.053 | [−0.002, +0.105] | 0.0088 | 0.0177 | +0.10 negligible | 70/124 |
| c1 high − 基準線① | 命題 GED | −0.022 | [−0.045, −0.001] | 0.1488 | 0.1488 | −0.08 negligible | 60/124 |
| c1 high − g1 ≥4 | 無向 AP（macro） | +0.152 | [+0.074, +0.231] | 0.0007 | 0.0030 | +0.23 small | 67/124 |

`c1 high − v3` は p(Holm) が 0.05 を下回るが、平均差の 95%CI は 0 を含む。
micro の値で比べると差は +0.038（0.511 対 0.473）であり、改善があるとは主張しない。
`c1 high − g1 ≥4` の差の大半は macro 平均の人工物である（§15.1(c)）。

主要な所見は 3 つである。

**(a) 命題対を選ぶ能力では、LLM は「隣接を全部つなぐ」に有意に劣る**
（無向 F1 0.458 対 0.508、差 +0.054、p(Holm)=0.0093）。
LLM の精度は基準線②より高い（0.473 対 0.410）が、再現率が大きく下回る（0.444 対 0.667）。

**(b) 一方、種別と向きの判定では基準線②を大きく上回る**（厳密 F1 0.296 対 0.151）。
つまり **LLM が付加しているのは「どの対か」ではなく「どういう関係か」**である。

**(c) 関係を出すとグラフ全体の編集距離は有意に悪化する**
（命題 GED −0.082、p(Holm)<0.0001）。関係 F1 が 0.3 台では、
1 本当てて得る利得より外して払う損の方が大きい。

### 5.2 誤りの内訳（RQ2）

![図3](figures/rep_fig3_error_budget.png)

v3・n=124 における内訳である。

| 正解 1,090 本の行方 | 本数 | 割合 |
| --- | --: | --: |
| 種別・向きとも当てた | 313 | 29% |
| 対と向きは当てたが種別を誤り | 82 | 8% |
| 対は当てたが向きが逆 | 89 | 8% |
| **そもそも対を見つけていない** | **606** | **56%** |

| 生成 1,023 本の行方 | 本数 | 割合 |
| --- | --: | --: |
| 当たり | 313 | 31% |
| 種別・向きの誤り | 171 | 17% |
| **正解に対応が無い（過剰生成）** | **539** | **53%** |

誤りの本体は未検出（正解の 56%）と過剰生成（生成の 53%）である。
一方、**対は当てたが種別・向きを誤った 171 本は、ラベル付けのみの改善で回収しうる**。
仮にこの 171 本をすべて正しく付け直せたとすると厳密 F1 は 0.296 → 0.458 となり、
これが本パイプラインにおける最大の単一の伸び代である。

### 5.3 距離帯 — 遠い関係はほとんど拾えない

![図4](figures/rep_fig4_distance.png)

関係が結ぶ 2 命題の発話順の距離で分けると、ゴールドの分布は
距離 1 が 68%、2–4 が 21%、5–9 が 8%、10+ が 3% である。

| 距離 | 正解 | v3 の生成 | v3 の AR | v3 の AP |
| --- | --: | --: | --: | --: |
| 1 | 745 | 619 | 0.325 | 0.394 |
| 2–4 | 227 | 273 | 0.269 | 0.216 |
| 5–9 | 86 | 91 | **0.093** | **0.088** |
| 10+ | 32 | 40 | 0.062 | 0.050 |

**距離 5 以上の帯は AP・AR とも 0.1 未満でほとんど機能していない。**
ただしこの帯は正解の 11% にすぎず、全体への寄与は小さい。
全体を引き上げるなら、正解の 68% を占める距離 1 の精度 0.394 を上げる方が本筋である。

帯ごとの AP は、不具合 §15.2(e) の修正で下がった（修正前: 0.433 / 0.254 / 0.108 / 0.083）。
修正前は端点が対応付かなかった生成側の関係 130 本が分母から漏れており、過大に出ていた。

なお基準線②は隣り合う**命題**どうしをつなぐので、ほぼ距離 1 の関係しか生成しない
（命題を持たない発話を挟む場合だけ 2 以上になる）。
それでも無向 F1 で LLM を上回るという事実が、§5.1(a) の所見の強さを示している。

## 6. 考察

### 6.1 LLM が付加している価値はどこにあるか

本研究の中心的な所見は、**LLM の貢献が層によって明確に分かれる**ことである。

- **命題の再構成・発話行為の判定**: 基準線と区別が付かない。
  発話をそのまま命題とみなす単純な規則で同等の値が出る。
- **命題対の選択**: 自明な規則（隣接を全部つなぐ）に有意に劣る。
- **関係の種別と向きの判定**: 基準線を大きく上回る（厳密 F1 +0.145）。唯一の明確な貢献。

この分解は、LLM を議論グラフ抽出に使う際の設計指針を示唆する。
**対の選択を LLM の自由生成に任せる必要はない**のかもしれない。
候補を別の手段で列挙し、LLM には種別と向きの判定だけを任せる構成が考えられる
（ただし本研究で試した候補対分類は、候補を提示すると「関係がある」と答えすぎるため
うまくいかなかった。§7.3）。

### 6.2 関係 F1 0.30 という水準の意味

人手一致 CASS = 0.56 を上限の目安としても、厳密 F1 0.296 は低い。
この水準の議論グラフを下流タスクに使う場合、
**拾ってくる関係の約 7 割はゴールド基準では誤りでありうる。**

したがって、議論グラフを用いた手法が下流タスクで効果を示したとしても、
「正しい議論構造が効いた」とは主張できない。
「粗い関係でも近傍を広げる効果があった」という弱い形にとどめるべきである。
逆に効果が出なかった場合も、議論構造が無効であることの証拠にはならない。

### 6.3 過剰生成の抑制には動作点の設計が要る

関係を出すとグラフ全体の編集距離は有意に悪化する（§5.1(c)）。
一方で、確信度 high のみに絞ると生成を 1,107 → 546 本に半減させ、
命題 GED は 0.386 → 0.460 まで回復し、**基準線①との差は統計的に有意でなくなる**
（−0.022, p=0.149）。

ただしこの改善は再現率との引き換えであり（無向 AR 0.460 → 0.256）、
関係 F1 は 0.280 → 0.235 と下がる。
**「関係を出しながらグラフを壊さない」ことは可能だが、拾える関係は半分になる。**
用途に応じて動作点を選ぶ設計（閾値を生成後に動かせる構成）が実用上は重要である。

## 7. 限界（抽出）

### 7.1 コーパスと一般化

- **英語コーパスである。** QT30 は BBC の放送討論であり、対象言語も文化も
  日本語の議事録等とは異なる。日本語の AIF ゴールドは公開されていないため、
  同等の検証には自前で少量のゴールドを作る必要がある。
- **ゴールド自体が上限を持つ。** 人手一致は CASS = 0.56 である。
  本研究の F1 を 1.0 と比較するのは適切でない。
- **ゴールドにメタモデル違反がある。** 取得した 274 ノードセットを検査すると
  158 件の違反があった（YA の anchor/illocute が 1 対 1 でない、TA が L→L でない等。
  `aif-eval -goldcheck`）。一方 LLM 生成グラフの違反は 0 件である（構成的に妥当な形しか作らないため）。
- **対象は 1 コーパスの 6 エピソードのみ**であり、他ドメイン（議会・法廷・SNS）への
  一般化は検証していない。

### 7.2 条件設定の限界

- **主要な結果は `gold-loc` 条件（発話分割を与える）のものである。**
  分割も LLM に任せる e2e 条件では関係 F1 が 0.216 まで落ちる（n=60）。
  実運用では分割も自動化する必要があり、本報告の数値は上振れした条件での値である。
- **モデルは 2 種のみ**（gpt-5.6-luna / terra）。温度・few-shot・他ベンダのモデルは未検証。
- **LLM 条件間の差は検出限界の下にある。** v3 / w1 / g1 / c1 の厳密 F1 は 0.280–0.298 で、
  差はすべて 0.052 未満である。これらの条件間に優劣があるとは主張できない。

### 7.3 試したが機能しなかった設計

次の設計は本研究では機能しなかったが、**実装や指示の与え方によっては成立しうる**。
「この方向性が無効である」という結論ではない。

- **生成後の検証パス**（候補を 1 本ずつ keep/drop）: 正しい関係と誤った関係を
  ほぼ同じ割合で削るため、精度が上がらない。
- **候補対分類**（距離 4 以内の候補を 1 対ずつ判定）: 候補を提示すると
  「関係がある」と答えすぎる。距離 2–4 の帯で正解 114 本に対し 391 本を返した。
  二値判定に特有の yes 寄りのバイアスと考えられる。
- **5 段階の依存度**: §5.4 のとおり、境界の位置が合わなかった。

# 第 II 部　グラフ比較の精度と手法

## 9. 課題 — 議論グラフの比較に固有の難しさ

GED は「ノードの挿入・削除・置換」と「辺の挿入・削除・置換」のコストの総和であり、
設計の自由度が大きい。グラフ同士の比較には GED が使われるが、
コストの置き方・正規化の仕方に標準がない。
本研究では実装を 3 度改訂したが、**そのたびに条件の順位が変わった**。
この経験から、議論グラフの評価には次の落とし穴があることが分かった。

- 置換コスト 0 のノード（内容を持たない構造ノード）を最適割当に載せると、
  最適解が縮退してソルバーが任意の割当を返し、正しい辺が誤りとして数えられる。
- 辺の一致を二値（完全一致か全損か）にすると、辺を 1 本足す期待コストが
  `P(1−2p)`（P は本数、p は精度）となり、**精度 0.5 が損益分岐点**になる。
  この 0.5 は「挿入コスト = 削除コスト = 1」と置いたことの副産物であって、
  議論構造の性質ではない。
- 正規化の分母に生成側の大きさを含めると、**出力量を増やすだけで値が改善する**。

## 10. 手法

### 10.1 グラフ編集距離の計算手順

生成グラフ A をゴールド B に変形する編集コストを、二部グラフ近似
（Riesen & Bunke, 2009）で求める（`internal/evaluation/aifged.go`）。

1. I-node と L-node のテキストを埋め込み、生成 × ゴールドのコサイン類似度表を作る。
2. 全ノードについて (n+m)×(n+m) のコスト行列を組み、最適割当を Hungarian 法で 1 回だけ解く。
   左上 n×m が置換コスト、右上・左下の対角が削除・挿入コストである。
3. 0.1 はその割当をそのまま使う。0.2 以降は **L と I の割当だけ**を使い、
   構造ノード（S / TA / YA）の対応は構造から導出する（§10.3）。
4. その対応のもとで、ノードと辺の編集コストを数える（§10.4）。
5. ゴールド基準で正規化する（§10.5）。

段階 1・2 の命題（と発話）の対応付けの詳細、その対応が各指標でどう使われるか、
閾値つきの命題 P/R/F1 の数え方は付録 B にまとめた。

種別の違う置換は禁止コストにしてあるので、コスト行列は種別ごとのブロック対角になり、
全ノードで解いても L だけ・I だけで解いても L↔L / I↔I の割当は同じになる。

**最適割当の実装。** 報告した数値は、割当を Python（scipy の `linear_sum_assignment`）の
小さなサービスで解いて得た。現在の実装は同じ解法（Crouse の最短増加路法）を Go に移植したもので
（`internal/evaluation/assignment.go`）、同点の解き方まで scipy と同じにしてある。
移植の前後で、合成データ 72 通りの比較結果が全フィールドで一致することを確かめた。
旧サービスは片側 400 ノードを超えると黙って打ち切っていたが、移植版は打ち切らない。
本実験のグラフは最大でもゴールド 181・生成 213 ノードで、打ち切りは一度も起きていない。
報告時の生成物を移植版で再評価すると、§15.2 の不具合に関わるフィールド以外は
全 8,928 行（5 条件 × ノードセット × 指標版 × 重み × 閾値の変種）で旧サービスの結果と一致した。

### 10.2 編集コスト

| 編集操作 | コスト |
| --- | --- |
| ノード置換 I↔I / L↔L | `1 − cos(埋め込み)`（負の cos は 0 に丸める） |
| S-node 同種 / 異種 | 0 / 0.75 |
| YA 同一の力 / 同系統 / 別系統 | 0 / 0.5 / 1.0 |
| TA↔TA | 0 |
| 種別違いの置換 | 禁止（1e6） |
| ノード挿入・削除 | 一律 1.0 |
| 辺 挿入・削除 | 1.0 |
| 辺 種別違い / 向き違い | 0.75 / 1.0（**両粒度で同値**） |

I-node / L-node の置換コストを埋め込み類似度で決めるのは、AIF 議論グラフの検索で
使われる設計（Bergmann et al.; Lenz et al., 2019）に合わせたものである。
YA の発話行為は、同系統（主張系 / 質問系 / 同意系）の取り違えを系統違いより軽くする。

感度分析として、YA / TA の削除コストを 0.5 に下げた重み（`ya-ta-discounted`）も同時に計算する。

### 10.3 構造ノードの対応の導出（0.2 以降）

AIF では S-node は前提と結論の I-node で、TA は前後の L-node で、YA は anchor と
illocute 先で、それぞれ一意に決まる。探索の対象ではないので、Hungarian 法には載せずに導出する。

- **S-node**: (前提の集合, 結論) の対応先が一致するゴールドの S-node に対応させる。
  前提 1 本の関係は、向きだけが逆のものも対応とみなす（種別違い・向き違いは置換コストで払う）。
- **TA**: 前後の L-node が対応していれば対応。
- **YA**: (anchor, illocute 先) がともに対応していれば対応。

### 10.4 粒度と辺の照合

GED は 2 つの粒度で測る。

| 粒度 | ノード | 辺 |
| --- | --- | --- |
| 命題グラフ（主指標） | I-node | 関係を命題間の辺 1 本に畳んだもの（RA は前提ごとに 1 本） |
| 全体グラフ（0.3） | L / TA / I と、発話に anchor され命題を illocute する YA | 対話層の辺 + 関係を畳んだ辺 |

全体グラフでは、関係を S-node と辺 2 本ではなく辺 1 本に畳む。こうしないと、
同じ 1 本の種別の取り違えが命題単位では 0.75 なのに全体では 4.75 になる。
遷移に anchor される YA も外す。生成側は「隣接しない発話どうしの関係には TA が無いので
YA も作らない」という構成規則で個数が決まり、ゴールドとの差が LLM の誤りを表さないためである
（発話行為は §10.6 の層別指標で別に測る）。

辺の照合では、同じ端点対に正解の辺があれば削除 + 挿入ではなく置換として扱う（0.2 以降）。
照合は **「完全一致」→「種別違い」→「向き違い」の順にパスごとに全件**で行う。
これで出力の順序によらず、安いコストの対応から先に確定する（§15.2(f) で修正）。

### 10.5 正規化

**正規化はゴールド基準**とする。

```
正規化 GED = GED ÷ （ゴールドを何も無いところから作るコスト = ノード数 + 辺数）
類似度    = 1 − 正規化 GED
```

参照側の大きさで割るのは WER / TER と同じ思想で、分母が条件によらず一定になる。
0〜1 には収まらず基準線より悪いグラフは負の値を取りうるが、それは表現できた方が正しい。
0.2 までの主指標だった対称正規化（分母に「生成側を全部消すコスト」を含む）も参考として併記する。

### 10.6 層別の指標（CASS に倣う）

GED は単一の数値なので「どこが悪いか」が分からない。argument mining の標準的な
評価指標 CASS（Duthie et al., 2016）がセグメンテーション・議論構造・発話行為を
別々に採点してから合成するのに倣い、層ごとの P/R/F1 を併記する。

| 層 | 正解の定義 |
| --- | --- |
| 発話分割（L） | 対応付いた L-node（cos ≥ 0.55） |
| 命題（I） | 対応付いた I-node（cos ≥ 0.55。数え方は付録 B.6） |
| 発話行為（YA） | 対応付いた命題上での発話行為の一致 |
| 関係（厳密） | 種別（RA/CA/MA）と向きの**両方**が一致 |
| 関係（向きのみ） | 種別を無視し、向きが一致 |
| 関係（無向） | 種別も向きも無視し、**命題対**を当てたか |

**精度 AP と再現率 AR は micro（全ノードセットの TP/FP/FN をプール）で報告する。**
per-nodeset 平均（macro）は、関係を 1 本も出さないノードセットで精度が 0 と記録されるため、
強く絞り込む条件を不当に低く見せる（§15.1(c)）。`aif-eval -report` は両方を書き出す。

関係の照合規則:

- **ゴールドの関係は 1 本につき 1 回しか当てない。** 生成側が同じ命題対に 2 本張っても、
  TP が正解の本数を超えない。
- 照合は「厳密 → 向きのみ → 逆向き」の順にパスごとに行い、
  厳密 TP・向きのみ TP・無向 TP がこの順に辞書式に最大になるようにする（§15.2(f) で修正）。
- **関係の端点の対応には、命題の閾値（cos ≥ 0.55）を課していない。** Hungarian 法の割当を
  そのまま使う。置換コスト（最大 1）は削除 + 挿入（2）より常に安いので、命題は必ず
  min(生成数, 正解数) 組が対応する。このため、命題の内容が対応していなくても、
  関係の位置関係が合っていれば関係は当たりと数えられうる（§16.1）。

### 10.7 距離帯

関係が結ぶ 2 命題の発話順の距離（TA の連鎖で並べた L-node の位置の差）で、
1 / 2–4 / 5–9 / 10+ の帯に分けて数える。全体の F1 は隣接の山に支配されるので、
「遠い関係を拾えていない」という失敗はここでしか見えない。

```
帯ごとの再現率 = 当たり（ゴールド側の帯） / 正解本数（ゴールド側の帯）
帯ごとの精度   = 当たり（生成側の帯）     / 生成本数（生成側の帯）
```

分子と分母は必ず同じ側の帯で数える（§15.1(a)）。生成本数には、端点がゴールドに
対応しなかった関係も含める（§15.2(e)）。

## 11. 指標の版の変遷

同じ生成グラフを 3 つの実装で測り直す実験（実験 M）を行った。LLM は一切叩かない。

| 版 | 変更点 | 直した欠陥 |
| --- | --- | --- |
| 0.1 | 全ノードを Hungarian 法に載せる。辺は完全一致か全損か。対称正規化 | — |
| 0.2 | L / I だけを割り当て、構造ノードは導出する。命題グラフの辺に部分点 | 構造ノードの縮退（§9 の 1 点目）、辺の全損（2 点目） |
| 0.3 | ゴールド基準の正規化を主指標に。全体グラフにも部分点。遷移に anchor される YA を外す | 分母が生成側の大きさに依存（3 点目）、粒度間の不整合 |

0.1 では TA どうしが置換コスト 0 で互いに区別できず、両端の L が正しく対応していても
間の TA が別物に割り当てられ、L→TA→L の辺が誤りとして数えられていた
（ゴールドの発話をそのまま使う基準線①ですら辺の精度 0.386）。

## 12. 結果

### 12.1 指標の定義が条件の順位を決めている（RQ3）

![図1](figures/rep_fig1_normalization.png)

同一の生成グラフを 3 版の実装で測った命題 GED 類似度である。

| 条件 | 対称正規化 0.1 | 0.2 | 0.3 | **ゴールド基準** 0.1 | 0.2 | **0.3** |
| --- | --: | --: | --: | --: | --: | --: |
| 基準線①（関係なし） | **0.689** | 0.689 | 0.689 | **0.483** | **0.483** | **0.483** |
| 基準線②（隣接を全部） | 0.568 | 0.660 | 0.660 | 0.012 | 0.217 | 0.217 |
| v3 | 0.672 | **0.705** | **0.705** | 0.335 | 0.401 | 0.401 |
| w1 | 0.671 | 0.704 | 0.704 | 0.323 | 0.391 | 0.391 |

**対称正規化 0.2・0.3 では v3 が最良、ゴールド基準では基準線①が最良**になる。
対称正規化の分母は生成側の大きさを含むため、関係を多く出す条件が持ち上がる。
同じグラフ・同じ編集コストに対して、**分母の定義だけで順位が入れ替わる**。

0.1 → 0.2 の改訂（構造ノードを最適割当から外す、辺に部分点を入れる）でも順位は動いた。
対称正規化 0.1 では基準線①が最良（0.689 対 v3 0.672）だが、0.2 では v3 が上回る。
**本研究は結論を 2 度書き換えている。**点推定の符号を主張の根拠にしてはいけない、
というのが最も確かな教訓である。

### 12.2 命題層の優劣は閾値の選び方で入れ替わる

![図6](figures/rep_fig6_threshold_curve.png)

命題が「対応付いた」と数える閾値を動かすと、命題 F1（macro）の順位が入れ替わる。
既定の cos ≥ 0.55 では LLM（v3 0.903）が基準線①（0.880）を上回るが、
cos ≥ 0.80 では逆転する（0.556 対 0.586）。
ゴールドの命題の約 44% は発話とほぼ同文（基準線①の cos ≥ 0.90 の F1 が 0.440）であり、
LLM はそこも書き換えてしまうためである。
`w1` は cos ≥ 0.90 の帯を 0.323 → 0.386 に改善したが、基準線①の 0.440 には届かない。

既定の 0.55 は、同一ノードセット内で*実際に関係がある*命題対の平均 cos（0.44〜0.48）の
すぐ上でしかない。1 点の値で「命題層は実用水準」とは言えない。

### 12.3 GED は層ごとの改善に鈍い

E1 で関係層が改善した（関係 F1 +0.080）のに対し、命題 GED の変化は −0.006 にすぎなかった。
GED は関係の誤りとノードの誤りを 1 つの数に混ぜるので、層ごとの改善を映しにくい。

## 13. 考察 — 指標の設計が結論を決める（RQ3）

本研究で最も一般性のある知見は、**測り方の欠陥が測られる対象の性質として報告されうる**
ことである。実装を 3 度改訂する過程で、次の主張がいずれも撤回された。

| 版 | 出していた主張 | 実際 |
| --- | --- | --- |
| 0.1 | 「LLM が関係を足すと命題 GED は悪化する」 | 辺の全損ルールの副産物 |
| 0.1 | 「全体 GED では LLM が基準線を大きく上回る」（large, p=0.001） | 構造ノードの対応付けの縮退で基準線が不当に罰せられていた |
| 0.2 | 「命題 GED では LLM が基準線を上回る」 | 分母が生成側の大きさを含むため |
| 0.2 | 「命題 GED がプロンプト版の順序を単調に並べる」 | 同上 |

議論グラフの評価指標を設計する際には、少なくとも次の 3 点を点検すべきである。

1. **置換コスト 0 のノードを最適割当に載せない。** 構造から一意に決まるノードは
   探索ではなく導出で対応させる。
2. **辺の一致を二値にしない。** 「関係の存在は当たっているが種別・向きが違う」が
   誤りの主要な形（本研究で 171 本・生成の 17%）なので、部分点を与えないと
   実際の改善が指標に映らない。
3. **参照との一致を測る指標の分母に、被検側の大きさを入れない。**
   出力量が条件間で変わる実験では、それがそのまま「改善」として計上される。

## 14. 評価指標の設計についての推奨

本研究の経験から、議論グラフの評価には次の構成を推奨する。

1. **GED は「全体として壊れていないか」の確認に使い、改善の測定には使わない。**
   GED は層ごとの改善に鈍い（§12.3）。層別の P/R を主指標に置くべきである。
2. **基準線を層ごとに置く。** 「関係を出さない」は関係抽出の基準線になっていない。
   「隣接を全部つなぐ」のような自明な規則を置いて初めて、
   LLM の寄与がどの層にあるかが分かる。
3. **単一の閾値で層の優劣を語らない。** 命題層の優劣は閾値で入れ替わる（§12.2）。
   閾値曲線を報告すべきである。
4. **micro / macro を明示する。** 強く絞り込む条件では両者が大きく乖離する（§15.1(c)）。
5. **照合を出力の順序に依存させない。** 貪欲な照合は、先に処理した要素が後の要素の
   完全一致を奪いうる（§15.2(f)）。

## 15. 計測上の不具合とその影響（監査結果）

本研究の指標実装には、報告の過程で発見・修正した不具合が複数ある。
**発見前に算出した値を含む暫定報告を行っていたため、ここに明記する。**

### 15.1 報告前に修正したもの

**(a) 距離帯ごとの精度の分子・分母の帯の不整合（修正済み）。**
当たりをゴールド側の距離帯で数えながら、分母を生成側の距離帯で数えていた。
このため基準線②で帯ごとの精度が 1 を超える（AP = 1.333）という不可能な値が出た。
修正後は分子・分母を同じ側の帯で揃えた（回帰テストを追加）。

**(b) ゴールドの距離分布の測定誤り（修正済み）。**
距離を**前処理前**のグラフで測っていたため、除去される孤立 L-node の分だけ
距離が水増しされていた。誤: 距離 10+ が 13.5%、正: **2.2%**。
この誤った分布に基づいて「LLM には近接バイアスがある」という仮説を立て、
遠距離の関係を促す規則をプロンプトに足す実験（E3 の v4）を行ったが、
**仮説の前提自体が誤りであった**。正しく測り直すと、v3 の生成の距離分布はむしろゴールドより
遠い側に厚い（距離 1: 生成 61% 対 正解 68%、2–4: 27% 対 21%、5–9: 9% 対 8%、10+: 4% 対 3%。§5.3）。
近接バイアスは存在しない。当該実験の結果（悪化）は過剰補正として整合する。
（この生成本数は (e) の修正後の値である。修正前は分母から漏れていたため、
「2–4: 生成 227 対 正解 227、5–9: 生成 74 対 正解 86」とほぼ一致するように見えていた。）

**(c) macro 平均が強い絞り込みを不当に低く見せる。**
関係を 1 本も出さないノードセットでは精度が 0 と記録される。
`g1 + 依存度 ≥4` は 124 件中 **36 件**で関係を 1 本も出さないため、
macro 精度 0.403 に対し micro 精度は 0.505 となる。
§5.1 の事前登録比較に含まれる `c1 high − g1 ≥4` の無向 AP +0.152 は
**大半がこの人工物**であり、micro で比べれば 0.511 対 0.505 とほぼ同等である。
同じく `c1 high − v3` の +0.053 も macro の差で、micro では +0.038 である。
本報告は micro を主指標とし、これらの比較の解釈を §5.1・§5.4 で訂正した。

**(d) 事前に登録した合格基準を満たしていない。**
`c1 + 確信度 high` の無向 AP は、部分標本（n=77）では 0.583 で
事前登録の基準（> 0.559）を満たしたが、**全標本（n=124）では 0.511 に下がり基準を満たさない**。
部分標本は 3 エピソードのうち 1 つが 5 件しか含まれない偏った集合であった。
中間報告の数値を結論として扱わなかったことで回避できた誤りである。

### 15.2 コードレビューで発見し修正したもの

本報告の公開に際してのコードレビューで、次の 2 件を発見し修正した（回帰テストを追加）。
修正後の実装で、報告時と同じ生成物（キャッシュ済みの LLM 応答と埋め込み・同じ 124 ノードセット・
同じプロンプト本文）を再評価し、本報告の数値・図・`data/metrics/*.csv` を差し替えた。
再評価に API の呼び出しは発生していない（全件がキャッシュから返った）。

**(e) 帯ごとの精度の分母から過剰生成の一部が漏れていた。**
端点がゴールドの命題に対応付かなかった生成側の関係は、帯ごとの生成本数（分母）に
数えられていなかった。v3 では生成 1,023 本のうち 130 本が漏れており、帯ごとの AP が過大だった。
**修正による変化**: §5.3 の帯ごとの AP（例: 距離 1 で 0.433 → 0.394）と図 4 の右図、§15.1(b) の生成本数。
帯ごとの AR、全体の AP / AR / F1、GED は変わらない。

**(f) 関係・辺の照合が出力の順序に依存していた。**
生成側が同じ命題対に種別の違う関係を複数出したとき（例: RA と CA）、先に処理した関係が
別種別のゴールドを「種別違い」として取ってしまい、後の関係の完全一致が数えられなかった
（再現例: 順序次第で厳密 TP が 0 または 1、命題 GED が 1.75 または 1.00）。
照合を「完全一致 → 種別違い → 向き違い」のパスごとに行うよう修正した。
**修正による変化**: 再評価した全 8,928 行のうち、g1 の 18 行と c1 の 12 行で厳密 TP が 1 本増え、
その一部で GED（0.2・0.3）が下がった（コストが小さくなった）。集計値では §5.1 の g1・c1（全部）の
厳密 AP/AR/F1 と c1 の命題 GED がそれぞれ +0.001 変わった。v3・w1・基準線②は変化しない。
0.1 は部分点を使わないため影響を受けない。結論に関わる数値はいずれも変わらない。

## 16. 限界（比較）

### 16.1 指標の設計上の限界

- **置換コスト 0.75 / 1.0 に理論的な裏づけがない。** 最大の誤りが RA ⇄ MA の
  取り違えである以上、この値は結果に直接効く。
- **正規化の分母は粒度で異なる**（命題グラフ 25.7、全体グラフ 131.6）ため、
  正規化後の値を粒度をまたいで比較することはできない。
- **命題の対応付けを埋め込みのコサイン類似度で行っている。** コサイン類似度は
  「同じ話題か」を測っており、IAT の命題再構成（一人称の解決・reported speech 化）を
  正しく評価できない（再構成した命題の方が、発話をコピーしただけのものより cos が低くなる）。
- **関係の照合は命題の閾値を見ない**（§10.6）。命題が内容として対応していなくても、
  割当で対応した命題どうしの関係は当たりと数えられうる。閾値以上の対応に限って
  関係を数える変種との比較は行っていない。
- **効果量 Cliff's delta は対応を使わない形で計算している。** 2 条件の値の分布全体を
  総当たりで比べており、対応のある比較の効果量としては保守的である。
  Wilcoxon 検定は正規近似で、同順位の分散補正を行っていない。

### 16.2 未実装の指標

- **発話分割の質を直接測る指標がない。** 境界 F1 / WindowDiff に相当する指標を
  実装しておらず、e2e と gold-loc の差からの間接的な推定にとどまる。
  第 I 部の「17% 過分割」は生成した L-node の件数比から述べたものである。
- **BERTScore や NLI による含意判定**による命題の対応付けは未実装である。
- **人手評価との突き合わせ。** 本研究の自動指標がアノテータの判断と
  どの程度一致するかは未検証である。

### 16.3 再現性

- 同一テキストの命題が複数あるとき、Hungarian 法の割当は同点の解き方で決まり、
  診断指標が ±0.003 程度動くことがある。現在の実装は同点の解き方を固定しており、
  同じ入力からは常に同じ値が出る。
- 事前登録 5 比較の Holm 補正は、`aif-eval -report` の出力（条件対ごとに全指標をまたいで補正）とは
  族の取り方が異なり、別途計算した。`data/metrics/*.csv` から再計算すると、
  掲載値と CSV の丸め（小数 4 桁）の範囲で一致する。
- 本文の数値は `data/metrics/*.csv` と照合し、次の箇所を訂正した:
  §12.1 の対称正規化 0.1 の列（旧: 基準線② 0.659 / v3 0.705 / w1 0.703）とゴールド基準 0.1 の列、
  基準線②のゴールド基準 0.2・0.3（旧: 0.215）、§5.1 の勝ち数（旧: 75/124）、
  §5.4 の g1 =5 の無向 AR（旧: 0.027）、§5.5 の命題 F1 の差（旧: +0.025）、
  §8 の「未検出の 1/4 を拾う」（旧: 0.362 / +0.066）、§5.6 の確信度による改善（旧: macro の +0.053）。
- 公開時のコードレビュー（§15.2）の後、報告時と同じ生成物を修正後の実装で再評価した
  （2026-10-05。LLM 応答・埋め込みはすべてキャッシュから返り、API 費用は 0）。
  本文・図 2・図 4・`data/metrics/*.csv` はこの再評価の値である。図 1・3・5・6 は再生成しても
  バイト単位で同一だった。事前登録 5 比較の値も再評価の前後で変わらない。

| 種類 | 担い手 | 守られる保証 | 節 |
| --- | --- | --- | --- |
| プロンプトの規則 | LLM | 無い。LLM が従わなかった出力も、A.6 の機械的な処理を経てそのまま評価する | A.2〜A.5 |
| 構成規則 | ハーネス | ある。出力の形を決定的に決める | A.6・A.7 |

たとえば「CA と MA の向きは時間順（後の命題が src）」はプロンプトの規則であり、
ハーネスはこれを検査も補正もしない。逆に「TA は隣り合う発話の間にだけ張る」「1 発話から作る命題は高々 1 つ」は
構成規則で、LLM の出力によらず必ず成り立つ。

温度・seed は指定していない（モデルの既定値）。出力は Structured Outputs（JSON Schema strict）で受け、
列挙型のフィールドは下記の選択肢以外を返せない。

| v2 | `locution_v1` | `illocution_v2` | `relation_v2` | – | E1 |
| **v3** | `locution_v1` | `illocution_v2` | `relation_v3` | – | E1〜E4 |

### A.2 stage 1 — 発話分割（`locution_v1`、e2e 条件のみ）

**入力**: 書き起こし全文。**出力**: 発話（L-node）の列。各要素は（話者, 本文）。

1. 話者のターンを、話者が新しい論点・主張・質問・応答に移るところで区切る。1 発話はおおむね 1 つの命題か 1 つの質問を表す。
2. 話者の言葉を保つ。言い換え・要約・文法の修正・文の結合をしない。ただし内容を持たない冒頭の談話標識（"Well," "I mean," "Again," "You know,"）と末尾のヘッジは落としてよい。
3. 発話でないもの（時刻、ト書き、拍手の記号、書き起こしの痕跡）は落とす。
4. 書き起こしの順序を保つ。
5. 各発話は、書き起こしに書かれたとおりの話者名に帰属させる。
6. 発話をでっち上げない。各発話の本文は、書き起こしの連続した抜粋（規則 2 で落とした語を除く）でなければならない。

### A.3 stage 2 — 発話行為と命題（`illocution_v2`。w1 以降は `illocution_v3`）

**入力**: 発話の列（番号・話者・本文）。gold-loc 条件ではゴールドの L-node をそのまま与える（並べ方は A.6.1）。
**出力**: 発話ごとに 1 件の（番号, 発話行為, 命題）。

#### A.3.1 発話行為（YA-node のスキーム）

- 付けるのは**その発話 1 つを持ち出す力**である。発話どうしの関係を表す力（Arguing / Restating / Analysing）は
  発話間の遷移に付くものなので、ここでは使わない。発話が先の発言の理由を述べていても、何かを述べているなら Asserting とする。
  推論の働きは stage 3 で RA として記録する。
- 選択肢は次の 8 種で、ちょうど 1 つを選ぶ（スキーマの列挙型もこの 8 種に限る）。

| 力 | 使う場面 |
| --- | --- |
| Asserting | 命題を真として、または自分の立場として述べる。**既定**で、理由・証拠・結論を述べる発話も含む |
| PureQuestioning | 立場を取らず、情報を求める質問 |
| AssertiveQuestioning | 話者の持つ立場を前提とする、または伝える質問 |
| RhetoricalQuestioning | 自らの答え（ふつうは否定）を主張するための質問。答えを期待しない |
| Challenging | 自分の立場を述べるのではなく、述べられたことの根拠・正当化を求める |
| Agreeing | 発話の内容全体が、他の話者の直前の発言への明示的な同意（"yes, exactly" "I agree with that"） |
| Disagreeing | 発話の内容全体が、他の話者の直前の発言の明示的な否定（"no, that is not right"） |
| Default Illocuting | 命題内容はあるが、上のどれにも当たらない |

- Agreeing / Disagreeing は、**発話そのものが同意・不同意の手であるとき**だけに使う。
  実質的な立場を述べ、それがたまたま他者の立場と衝突するだけなら Asserting とし、衝突は stage 3 で CA として記録する。

#### A.3.2 命題（I-node）

発話を、IAT の reported speech の慣行に従って、独立した平叙文 1 文に書き直す。

1. 遂行的な枠を外す。"I think the schools should reopen" → "the schools should reopen"
2. 一人称・二人称と直示表現を、名前の付いた参加者に解決する。"I have not worn one"（Camilla Tominey の発話）→ "Camilla Tominey has not worn a face mask"
3. 代名詞と省略を、前後の発話を使って解決する。
4. 質問は、問いではなく問われている命題を書き、未知の部分を `xxx` とする。"who here has worn a mask?" → "a face mask has been worn by xxx so far"
5. 小文字で 1 文。引用符と帰属節（"X says that ..."）は付けない。誰の発言かは L-node が担う。
6. 命題内容がまったく無い発話（議事進行、挨拶、発言権の管理。例 "Let's take the next question"）は、命題を空文字列にし、発話行為を Default Illocuting にする。

#### A.3.3 w1 で足した規則（`illocution_v3`）

7. **変えるのは最小限にする。** 命題は発話の内容であって、その要約や改善ではない。発話がすでに独立した平叙文として読めるなら、逐語で写す。
   同義語への置換、節の並べ替え、形式化、圧縮をしない。編集するのは規則 1〜6 が強いるところだけとする。

プロンプトはこの規則の根拠として「注釈済みの命題のおよそ半分は、元の発話と逐語で同じであり、
それを書き換えると注釈は良くならず悪くなる」と述べている。これは**ゴールドの観察から得た統計をプロンプトに含めた**ものである
（§12.2 の「ゴールドの命題の約 44% は発話とほぼ同文」と同じ観察）。

### A.4 stage 3 — 命題間の関係（`relation_v3`）

**入力**: 命題の列。各行は（番号, stage 2 の発話行為, 話者, 本文）で、番号は**発話された順**に 0 から振る
（命題を持たない発話は飛ばして詰める）。プロンプトは「番号が大きいほど後に発話された」と明示する。
**出力**: 関係の列。各要素は（src, dst, 種別, 関係の発話行為, 根拠 1 文）。

#### A.4.1 種別と向き

| 種別 | 意味 | src → dst | 向きの決め方 | 関係の発話行為 |
| --- | --- | --- | --- | --- |
| RA（Default Inference） | src が dst を**支持する理由**として示されている | 前提 → 結論 | **論理**: 「src だから dst」と読めるか。「dst だから src」の方が自然なら入れ替える。結論が先に来ても理由が先に来てもよい | Arguing |
| CA（Default Conflict） | src と dst が**両立しない**（一方を主張することが他方を退ける理由になる） | 攻撃する側 → 攻撃される側 | **時間順**: 後の命題が前の命題を攻撃する（src の番号が大きい） | Disagreeing。衝突が根拠の要求として表れるときは Challenging |
| MA（Default Rephrase） | src が dst を**言い換える・再述する・再定式化する** | 言い換え → 元の内容 | **時間順**: 後の言い換えが src（src の番号が大きい） | Restating。質問と応答の場合（A.4.2）は Default Illocuting |

#### A.4.2 見落としやすい MA の 2 規則

1. **質問と応答の間にも MA が成り立つ。** 質問の力（PureQuestioning / AssertiveQuestioning / RhetoricalQuestioning）で発話された命題に後から答えがあれば、
   答えは問われた命題を具体化している。答えを src、質問の命題を dst、関係の発話行為を Default Illocuting として MA を出す。
2. **言い換えの連鎖はよくあり、すべて記録する。** 話者は同じ内容を、狭め、広げ、精度を足しながら言い直す
   （"people can meet outdoors" → "two households can meet outdoors" → "no more than eight people can meet outdoors"）。
   後の言い直しはそれぞれ、直前の言い直しを指す 1 本の MA とする。単なる繰り返しとして飛ばさず、RA としても記録しない（精度を足すことは理由ではなく再定式化である）。

RA と MA の判定には次の問いを使う。話者は**同じことを別の言葉で言い直している**のか（MA）、**別のことを受け入れる理由を与えている**のか（RA）。
受動態への言い換え、一般化、特殊化、要約、質問への答えはすべて MA である。RA は、src が無ければ dst の支持が弱まるときだけに出す。

#### A.4.3 一般規則

1. **この対話の中で**実際に成り立つ関係だけを結ぶ。話題が近いことは関係ではない。2 つの命題が同じ話題について述べているだけ、または一方が他方の話を続けているだけなら結ばない。
2. 関係の大多数は、対話の中で**近い**命題どうし（連続しているか、ほぼ連続している命題）に成り立つ。離れた命題どうしの関係には明確な理由が要る。
3. 関係は話者をまたいでも、同じ話者の中でも成り立つ。同じ話者が連続する 2 発話で自分の論点を展開するのは、ふつう RA（一方が他方の理由）か MA（後が前を再述）である。
4. 命題とそれ自身を結ばない。
5. すべての命題をグラフに入れようとしない。支持も攻撃も再述もせず、新しい情報を足すだけの命題はつながずに残す。
6. 複数の命題が 1 つの結論を共同で支持するときは、前提ごとに 1 本ずつ、同じ dst の RA を出す。

### A.5 関係の等級（E5）

等級は関係ごとに S-node に付け、閾値は生成後に動かす（c1 は「high のみ」「medium 以上」「全部」、
g1 は「=5」「≥4」「≥3」「≥2（＝全部）」）。閾値で落とした関係は、それを担う YA も一緒に落とす。

#### A.5.1 c1 — 確信度 3 値（`relation_v8` = `relation_v3` + 確信度）

- 確信度の対象は、**関係が成り立つこと**と**その種別と向きが正しいこと**の両方である（2 つの命題が何らかの形でつながっていることではない）。
- `high` — このガイドラインに従う注釈者なら、この種別・この向きで確実に記録する。
- `medium` — 関係はあるが種別か向きに自信が無い、または注釈者が記録しないことも十分ありうる。
- `low` — この関係が注釈されていなくても驚かない。
- 確信度を判断の回避に使わない（種別と向きは 1 つに決める）。逆に、自信が無いことを理由に関係を差し控えず、`low` で記録する。

#### A.5.2 g1 — 依存度 5 段階（`relation_v7` = `relation_v3` + 依存度）

注釈者の確信ではなく、**dst が src にどれだけ依存しているか**という関係そのものの性質を等級にする。
各段の判定手順を当て、当てた手順を `test` フィールドに 10 語以内で書く。

| 等級 | 定義 | 判定手順 |
| --- | --- | --- |
| 5 明示的で構成的 | 話者が関係を言葉で示している（"so" "because" "therefore" "that's why" "in other words" "no, that's not right"）、または src を除くと dst を支えるものが何も残らない | 接続語があるか。src が無いと dst が崩れるか |
| 4 構成的だが無標 | 接続語は無いが、dst は src を根拠に持ち出されている。src を除くと dst の役割が変わる（結論・応答・訂正でなくなる） | src を除くと、対話の中で dst がしていることが変わるか |
| 3 単独で立つ 2 主張の間の実際の関係 | どちらも独立した主張で、どちらも他方が無くても崩れないが、一方が他方を支持・再述・否定している。注釈者なら記録する | 両方が単独で立つとしても、注釈するなら記録するか |
| 2 読み直して初めて擁護できる | 2 つの命題は同じ話題を続けている、または後が前に情報を足しているだけで、支持・再述と読む読み方は作れるが、対話がその読みを求めていない | その読みに自分を説得する必要があったか |
| 1 関係ではない（出力しない） | ほぼ同文の繰り返し、発言権を渡すための司会による主張の引用、直前の発言の確認、単に先へ進む語り | 内容が同じか、単に隣り合っているだけか |

さらに次の 2 点を指示している。

- **等級 2 以上はすべて出し、正直に付ける。** 弱い関係を省かず 2 として記録する。記録を正当化するために弱い関係を 3 や 4 に上げない。
- **記録したくなる関係の大半は 2 と 3 である。** 4 と 5 は、判定手順が実際に通るとき（本文に接続語がある、src が無いと dst が働かない）に限る。

後者の注意書きは、等級を 2・3 に寄せる方向に働きうる。§5.4 で観察した等級 3 への集中（69.3%）は、
段数の効果だけでなく、この指示の効果も含んでいる可能性がある。

### A.6 構成規則（ハーネスが機械的に課すもの）

#### A.6.1 入力の準備

- 前処理（`aif.Normalize`）で、ゴールドから孤立した L-node（次数 0）と AIF のメタモデルに無い形の辺を除く（§2.1）。
- gold-loc 条件では、ゴールドの L-node を、**すべての TA の向き（前の発話 → 後の発話）を満たす順**に並べて与える。
  TA で順序が決まらない発話どうしはタイムスタンプで、それも同じなら JSON の並びで決める。
  L-node の本文が「話者 : 本文」の形なら、話者と本文に分けて渡す。本文が空の L-node は渡さない。
- 発話が 120 個を超える入力は分析を拒否する（黙って切り詰めない）。

> 注: 本報告の数値は、旧い並べ方（各 L-node から最初の TA だけをたどり、たどれなかった発話を末尾に回す）で
> 作った入力から生成した。旧い並べ方は、TA が分岐・合流するゴールドで発話を末尾に回すことがあり、
> test 124 件のうち 64 件で入力の順序が現在の並べ方と異なる。

#### A.6.2 発話・遷移・命題の組み立て

1. L-node の本文は「話者 : 本文」とする。
2. **TA は、並べた発話の隣どうし（i 番目 → i+1 番目）に 1 本ずつ張る。** LLM には判定させない。
3. **1 発話から作る命題は高々 1 つ**とする。同じ発話番号への 2 件目以降の応答と、範囲外の番号は捨てる。
4. 命題が空の発話には、I-node も YA も作らない（AIF は内容を持たない YA を許さないため）。その発話の L-node と TA は残る。
5. 発話行為が IAT の発話行為の集合に無いときは、Default Illocuting に置き換える。
6. 命題は L→YA→I で発話に anchor する（YA のスキームは stage 2 の発話行為）。

#### A.6.3 関係の組み立て

1. 命題が 2 つ未満なら stage 3 を呼ばない。
2. 存在しない命題を指す関係、src と dst が同じ関係、種別が RA / CA / MA 以外の関係は捨てる。
3. （src, dst, 種別）が同じ関係は 1 本にまとめる。種別が違えば、同じ命題対に複数本を許す。
4. 関係ごとに S-node を 1 つ作り（スキームは種別の既定値 Default Inference / Default Conflict / Default Rephrase）、src → S-node → dst と辺を張る。等級（A.5）は S-node に載せる。
5. **関係を担う YA は、src と dst の発話が隣り合うとき（間に TA があるとき）だけ**、その TA に anchor して作る。
   スキームは、LLM が答えた関係の発話行為が遷移の力（Arguing / Restating / Disagreeing / Challenging / Analysing / Default Illocuting）ならそれを採り、
   そうでなければ Default Illocuting とする。隣り合わない発話どうしの関係には TA が無いので、YA も作らない。
6. **CA と MA の向き（時間順）、関係の種別と発話行為の対応（RA なら Arguing など）は検査も補正もしない。** これらはプロンプトの規則（A.4.1）である。
7. 最後に前処理と同じ正規化を掛け、メタモデル検査（A.7）を通す。

#### A.6.4 LLM を使わない基準線

- **基準線①**: ゴールドの発話（A.6.1 の順）をそのまま命題とし、すべて Asserting で anchor する。関係は出さない。TA は A.6.2 の規則 2 で張る。
- **基準線②**: stage 2 は w1 と同じ LLM 出力（`illocution_v3`）を使い、stage 3 だけを規則で作る。
  **命題の番号（A.4 の入力と同じ。命題を持たない発話は飛ばす）で隣り合う命題をすべて RA で結ぶ。**
  向きは後の命題 → 前の命題とする（dev のゴールドの実測で 73% がこの向き）。関係の YA は A.6.3 の規則 5 で作る。

#### A.6.5 主結果に含めない段階

- **検証パス**（v6、`verify_v1`）: stage 3 の関係を 1 本ずつ、2 つの命題の本文・発話間の距離・最初の根拠とともに示し、残すか捨てるかを判定させる。
  捨てる条件は、(1) 同じことを繰り返しているだけで論じていない、(2) つながりが話題上のもので議論上のものでない、
  (3) 隣り合っていることの副産物にすぎない、(4) 種別の誤りが取り返しのつかない形である、の 4 つ。
  残す条件として「距離は捨てる理由にならない（関係の 5 本に 1 本は 5 発話以上離れている）」と述べているが、
  この距離分布は §15.1(b) で誤りと判明したものである。
- **候補対分類**（p1、`candidate_v1`）: 命題の番号で 4 以内に離れた対をすべて候補として示し、対ごとに none / RA / CA / MA、
  src がどちらか（earlier / later）、確信度を判定させる。関係の発話行為は種別から機械的に決める（RA → Arguing、CA → Disagreeing、MA → Restating）。

### A.7 メタモデル検査（10 規則）

生成グラフは次の検査を通す（`internal/aif/validate.go`。Chesñevar et al., 2006 / Budzynska & Reed, 2011 / AIFdb のスキーマに基づく）。

## 付録 B　命題の対応付けアルゴリズム

生成グラフの I-node（命題）とゴールドの I-node を対応付ける手順を示す。この対応は第 II 部のほぼすべての指標の土台であり、
命題 GED、関係の P/R/F1、発話行為の一致率は、いずれもこの対応の上で数える（B.5）。
実装は `internal/evaluation/`（`similarity.go`・`aifged.go`・`assignment.go`・`diagnostics.go`）にある。
L-node（発話）の対応も同じ手順で求める。

### B.1 入力と出力

- **入力**: 生成グラフの I-node 集合 P = {p₁, …, pₙ} とゴールドの I-node 集合 G = {g₁, …, gₘ}（どちらも前処理後。§2.1）。
- **出力**: 1 対 1 の対応 M ⊆ P × G。各命題は高々 1 回しか現れず、対応しない命題は「削除」（生成側）または「挿入」（ゴールド側）として扱う。
- 対応は**命題の本文だけ**から決め、関係（辺）は見ない（理由は B.4）。

### B.2 手順

**段階 1 — 埋め込みと類似度。** 本文が空でない I-node と L-node の本文を、生成側とゴールド側をまとめて埋め込む
（既定設定は `text-embedding-3-small`、1,536 次元。1 件あたり 3,500 文字で切り詰める）。
I-node は本文をそのまま、L-node は「話者 : 本文」を埋め込む。生成 × ゴールドの同じ種別の組すべてについて
コサイン類似度 cos(p, g) を求める。埋め込みはディスクにキャッシュし（キーはモデル名・次元数・本文）、
同じ本文には常に同じベクトルを使う（API の戻り値はビット単位で同一とは限らず、割当が揺れるため）。

**段階 2 — コスト行列。** Riesen & Bunke (2009) の形で、(n+m)×(n+m) の正方行列 C を組む。

```
             g₁ … gₘ              ε₁ … εₙ（削除）
  p₁ … pₙ  [ 置換 c(pᵢ, gⱼ) ]   [ 対角に削除 1.0、他は禁止 ]
  ε₁ … εₘ  [ 対角に挿入 1.0、    [ すべて 0 ]
   （挿入）   他は禁止       ]
```

- 置換コスト c(p, g) = 1 − max(0, cos(p, g))。負の cos は 0 に丸める（「無関係」より悪くはしない）。値は 0〜1 に収まる。
- 削除・挿入のコストは 1.0（I-node と L-node は重みの設定によらず 1.0）。禁止は 1e9。
- 実装では I-node だけでなく全ノードを 1 つの行列に載せて解く（種別ごとの置換コストは §10.2）。
  種別の違う置換は禁止コスト（1e6）なので行列は種別ごとのブロック対角になり、I↔I の割当は I-node だけで解いた場合と
  （同点の解き方を除き）同じになる。

**段階 3 — 最小コスト割当。** C の最小コスト完全割当を、Crouse (2016) の最短増加路法で解く
（scipy の `linear_sum_assignment` の移植。同点のときの列の選び方まで同じにしてあり、同じ行列からは常に同じ割当が返る）。
計算量は O((n+m)³) で、本実験の最大のグラフ（ゴールド 181・生成 213 ノード）でも問題にならない。

**段階 4 — 対応の取り出し。** 割当のうち pᵢ → gⱼ（j ≤ m）の組を対応 M とし、I-node どうしの組だけを残す。
pᵢ → εᵢ は削除、εⱼ → gⱼ は挿入である。

```
function AlignPropositions(P, G):
    S ← cos(p, g) for all p ∈ P, g ∈ G           # 段階 1
    C ← (n+m)×(n+m) matrix filled with 1e9        # 段階 2
    for i, j: C[i][j] ← 1 − max(0, S[i][j])
    for i:    C[i][m+i] ← 1.0                     # 削除
    for j:    C[n+j][j] ← 1.0                     # 挿入
    for j, k: C[n+j][m+k] ← 0                     # ダミーどうし
    σ ← LinearSumAssignment(C)                    # 段階 3（Crouse の最短増加路法）
    return {(pᵢ, g_σ(i)) : i ≤ n, σ(i) ≤ m}       # 段階 4
```

### B.3 この割当の性質

1. **閾値を見ない。** 置換コストは最大でも 1.0 で、削除 + 挿入（2.0）より常に安い。したがって割当は必ず
   min(n, m) 組の対応を作り、cos がほぼ 0 の「内容がまったく違う」命題どうしも対応する。
   閾値（cos ≥ 0.55）は、この割当とは別に、命題の P/R/F1 を数えるときにだけ使う（B.5）。
2. **総和を最大にする。** 割当は cos の総和（＝ 1 − cos の総和の最小）を最大にする 1 つの対応であり、
   「閾値以上の対の数」を最大にする対応とは一般に一致しない（B.6 の例）。
3. **同点がある。** 本文が同一の命題がグラフ内に複数あると、置換コストが同点になり、どれに対応するかは同点の解き方で決まる。
   解き方は固定してあるので結果は決定的だが、同点の解き方を変えると診断指標が ±0.003 程度動くことがある（§16.3）。
4. **意味の同一性ではなく話題の近さを測る。** コサイン類似度は、IAT の命題再構成（一人称の解決・reported speech 化）を
   した命題よりも、発話を写しただけの命題に高い値を与えやすい（§16.1）。
5. **gold-loc 条件の L-node。** 生成側の L-node はゴールドの L-node と本文が同一なので cos ≈ 1 で対応し、
   発話の対応は実質的に恒等写像になる（test 124 件に本文が重複する L-node は無い）。
   ただし I-node の対応は L-node の対応から導かず、本文だけで決める（B.4）。

### B.4 なぜ辺の構造を割当に入れないか

Riesen & Bunke (2009) の二部グラフ近似は、置換コストにノードの周りの辺の照合コストを足す。本実装はこれを足さず、
ノードの本文だけで割り当てる。辺を足すと、命題の対応付けが関係の予測に引きずられ、
「関係が合うように命題を対応させる」ことになる。その対応の上で数える関係の P/R は過大になる
（評価したいものを割当が先取りする）。そこで命題の対応は内容だけで固定し、関係はその対応の上で数える。
この結果、得られる GED は辺まで含めて最適化した値の上界になる。

同じ理由で、gold-loc 条件でも I-node の対応を「同じ発話から出た命題どうし」として L-node の対応から導くことはしない。
この方式は e2e 条件（発話の対応自体が不確か）に使えず、条件間で対応の決め方が変わってしまうためである。

### B.5 対応の使われ方

| 用途 | 使う対応 | 閾値 |
| --- | --- | --- |
| 命題 GED のノードのコスト（§10.2） | 割当 M | 使わない（置換コスト 1 − cos で連続的に払う） |
| 命題 GED・全体 GED の辺の照合（§10.4） | 割当 M（全体 GED では L-node の割当と、そこから導出した構造ノードの対応も使う。§10.3。0.1 だけは導出せず、全ノードの割当をそのまま使う。§11） | 使わない |
| 関係の P/R/F1 と距離帯（§10.6・§10.7） | 割当 M で関係の両端をゴールドの命題に写す | **使わない**（§16.1） |
| 発話行為の一致率（§10.6） | 割当 M の各組について、発話（L-node）に anchor された YA の力を比べる | 使わない |
| 命題の平均 cos | 割当 M の組の cos の平均 | 使わない |
| 命題の P/R/F1・閾値曲線（§10.6・§12.2） | 閾値ごとに解き直す最大対応（B.6） | 使う（既定 0.55。曲線は 0.3〜0.9） |

### B.6 閾値つきの命題 P/R/F1

閾値 t での TP は、**cos ≥ t の組だけを使って作れる 1 対 1 の対応の最大数**とする。
置換コストを「cos ≥ t なら 0、それ以外は 3（削除 + 挿入の 2 より高い）」に置き換えた行列で B.2 の段階 3 を解く。
組を 1 つ増やすごとにコストが 2 下がるので、最小コストの解は組の数が最大の解になる。
FP = n − TP、FN = m − TP として P/R/F1 を求め、これを閾値ごとに繰り返す。

割当 M をそのまま閾値で切る方式との違いを、命題 2 つずつの例で示す。

| | g₁ | g₂ |
| --- | --: | --: |
| p₁ | cos 0.99 | cos 0.56 |
| p₂ | cos 0.56 | cos 0.50 |

割当 M は総和の大きい {p₁↔g₁ (0.99), p₂↔g₂ (0.50)}（コスト 0.51）を選ぶ（{p₁↔g₂, p₂↔g₁} はコスト 0.88）。
これを閾値 0.55 で切ると TP は 1 になる。一方、閾値以上の組だけで作れる最大対応は {p₁↔g₂, p₂↔g₁} で、TP は 2 になる。

> 注: 本報告の命題 P/R/F1 と閾値曲線（§5.5・§12.2・図 6）は、割当 M を閾値で切る旧い方式で計算した。
> 旧い方式は TP を過小に数えうる（上の例）。同様に、本報告の発話行為の一致率は、TA に anchor された YA（test のゴールドで 4 本）を
> 区別せずに比べていた。いずれも現在の実装（B.5・B.6）で再評価する必要がある。
